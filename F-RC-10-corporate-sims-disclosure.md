# F-RC-10 — Ответ регистрации отдаёт свежему устройству инвентарь корпоративных SIM всей установки

**Severity: Medium**

| | |
|---|---|
| Ручка | `POST /api/v3/enroll/code` |
| Дата подтверждения | 20.10.2026, перепроверено 21.10.2026 |
| Статус | подтверждено измерением |

---

## Суть

При регистрации устройства по коду приглашения сервер возвращает, помимо адресов
и конфигурации SCEP, поле `corporateSims` — **список корпоративных SIM всей
установки**: идентификаторы IMSI и ICCID. На стенде это 22 записи.

Получает их **любое устройство, прошедшее регистрацию**, — то есть тот, у кого
оказался одноразовый код приглашения. Своих SIM у свежего устройства ещё нет, и
для его работы инвентарь чужих SIM не требуется.

---

## Воспроизведение

```bash
python3 cli/mdmclient.py enroll --device https://<host> --code <код приглашения>
```

или напрямую:

```
POST /api/v3/enroll/code
User-Agent: Dalvik/2.1.0 (...)        ← обязателен, иначе HTTP 576
{"code": "<код>", "installationToken": "<любой uuid>"}
```

В ответе:

```json
{"data": {"kitId": 735, "scepServerConfig": {...},
          "corporateSims": [ {"imsi": "...", "iccid": "..."}, ... ]}}
```

Наш клиент печатает это явно:

```
в ответе пришли корпоративные SIM установки: 22 записей
```

---

## Влияние

* **Раскрытие инвентаря организации** стороне, которая только что
  зарегистрировалась и ещё ничем не подтвердила свою доверенность, кроме
  одноразового кода.
* IMSI и ICCID — устойчивые идентификаторы абонентов. По ним можно сопоставить
  корпоративные номера, оценить размер парка, а при наличии доступа к сети
  оператора — вести целевое наблюдение.
* Код приглашения — относительно слабый секрет: он передаётся сотруднику, живёт
  до использования и в ряде сценариев рассылается почтой.

---

## Рекомендации

1. **Не возвращать чужие SIM.** Устройству при регистрации нужны только его
   собственные параметры.
2. Если список нужен для политики «разрешённые SIM» — отдавать **хеши** или
   проверять принадлежность на сервере по запросу, не раскрывая весь инвентарь.
3. Пересмотреть остальные поля ответа регистрации на предмет лишних данных об
   установке.

---

## Примечание о границах

Находка относится к регистрации устройства, а не к самой фиче удалённого экрана,
но обнаружена в ходе работ по ней и затрагивает тот же путь (регистрация → mTLS →
командный канал), поэтому вынесена в этот же комплект.
