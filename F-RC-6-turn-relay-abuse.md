# F-RC-6 — Ретранслятор TURN используется как общий UDP-релей по суточному пропуску

**Severity: Medium**

| | |
|---|---|
| Компонент | coturn, `turn:sb-test.safe-mobile.ru:3478` (сам стенд) |
| Как получены креды | штатная ручка конфигурации сеанса консоли |
| Дата подтверждения | 21.10.2026 |
| Статус | подтверждено измерением |

> Внешний `turn.safe-mobile.ru` по требованию заказчика **не проверялся**.

---

## Суть

Логопас к ретранслятору выдаётся по модели coturn REST, где `username` — это
**unix-время + 86400**, а `credential` — HMAC от него. Такой пропуск:

* **не привязан** ни к сеансу, ни к устройству, ни к оператору;
* **действует сутки** (срок зашит в сам `username`);
* **выдаётся без начала сеанса** — достаточно вызвать ручку конфигурации;
* **переживает освобождение аллокации** — после `Refresh lifetime=0` те же креды
  снова дают `ALLOCATED`;
* попадает **и на устройство** — приходит в агент в каждом `WebRTCStart`.

При этом `CreatePermission` на произвольный внешний адрес проходит успешно, то
есть релей пересылает трафик на любой адрес в интернете, а не только второй
стороне сеанса.

---

## Воспроизведение

### Получение пропуска без сеанса

```
POST /api/v120/mcc/command/webrtc-signal
[<mccId>]
```

Ответ:

```json
{"iceServers": [{"urls": ["turn:sb-test.safe-mobile.ru:3478"],
                 "username": "1792672684",
                 "credential": "x5qQFvVAxcKjjFFe87pegPoJ/n0="}],
 "iceTransportPolicy": "relay",
 "connectTimeoutSeconds": 30, "reconnectTimeoutSeconds": 30,
 "roomId": 896}
```

`username` = `now + 86400`. Устройство при этом **не трогается** — ни команды, ни
записи в истории.

### Проверка релея

```bash
python3 cli/turnprobe.py --base <host:8443> --mcc <СВОЁ устройство> \
    --scenario creds        # креды переживают освобождение аллокации
python3 cli/turnprobe.py --base <host:8443> --mcc <СВОЁ устройство> \
    --scenario external     # разрешение на произвольный внешний адрес
```

Замеры:

| проверка | результат |
|---|---|
| `Allocate` с кредами из MDM | `ALLOCATED relay=85.198.96.253:57770 lifetime=600s` |
| освободить аллокацию, подождать, повторить | **снова `ALLOCATED`** теми же кредами |
| `CreatePermission 1.1.1.1:53` и `8.8.8.8:53` | **оба `succ`** |

Данные на внешние адреса **не отправлялись** — зафиксировано только разрешение;
этого достаточно, чтобы показать отсутствие ограничения по пиру.

## Влияние

Администратор с доступом к пульту (а равно любое скомпрометированное устройство
парка, которому пропуск приходит сам) получает **сутки пользования ретранслятором
организации** как обычным UDP-прокси:

* **атрибуция трафика** — исходящий трафик идёт с адреса установки MDM; жалобы,
  попадание в блок-листы и расследования прилетят владельцу;
* **сокрытие источника** — посторонний получает анонимизирующий транзит на
  респектабельной инфраструктуре;
* **расход канала и слотов релея**.

Наиболее реалистичный вектор — **устройство**, а не администратор: логопас
уходит в агент при каждом сеансе и хранится на устройстве (см.
[Low/Info](low-and-info-notes.md), замечание W-3).

---

## Чего эта находка НЕ даёт

Проверено отдельно и **закрыто негативом** — внутрь сети через релей попасть
нельзя:

| проверка | результат |
|---|---|
| `Allocate` без MESSAGE-INTEGRITY | `401` — открытого релея нет |
| метаданные `169.254.169.254`, `127.0.0.1`, `10/8`, `172.16/12`, `192.168/16`, `100.64/10`, `0.0.0.0` | `403` по UDP **и** по TCP |
| `::1`, `fd00::1` | `443` |
| пакет в чужую сессию без встречного разрешения | не доставлен — изоляция есть |

То есть `denied-peer-ip` настроен грамотно и на обоих транспортах. SSRF через
TURN **не подтверждается**.

Исчерпание пула релея сознательно не проверялось: отказ в обслуживании вне
ценности для программы, а шум на общем стенде нежелателен.

---

## Рекомендации

1. **Сократить срок жизни пропуска** с 24 часов до минут — сеанс длится десятки
   минут, сутки не нужны.
2. **Привязать пропуск к сеансу**: coturn REST допускает `username` вида
   `<timestamp>:<имя>` — выдавать уникальное имя на комнату.
3. **Не выдавать креды раньше фактического старта** сеанса и инвалидировать их по
   завершении.
4. **Включить квоты** (`user-quota`, `total-quota`, `max-bps`), чтобы утёкший
   пропуск не превращался в канал для объёмного злоупотребления.
