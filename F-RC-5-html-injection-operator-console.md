# F-RC-5 — Устройство внедряет произвольную разметку в окно оператора (сток `innerHTML` без экранирования)

**Severity: Low–Medium** (инъекция HTML с подменой интерфейса; исполнение скрипта
сдерживается **только** политикой CSP)

| | |
|---|---|
| Компонент | страница пульта `/remotecontrol`, `ui.js` + `WebRTCService.js` |
| Источник данных | **управляемое устройство** — наименее доверенная сторона |
| Дата подтверждения | 21.10.2026 |
| Статус | сток доказан в настоящем браузере; доставка измерена отдельно |

---

## Суть

Строку, которую формирует **устройство**, страница пульта выводит в DOM через
`innerHTML` без экранирования. Скомпрометированный или вредоносный агент на
телефоне может нарисовать произвольную разметку в доверенном окне консоли того
администратора, который этим телефоном управляет.

Модель доверия здесь перевёрнута: в MDM именно устройство считается потенциально
скомпрометированным — в этом смысл продукта.

---

## Цепочка по коду

**1. Устройство формирует текст.** При разрыве сеанса агент отправляет в
командный канал команду `113`:

```json
{"type": "Disconnect", "room": 893,
 "error": {"errorCode": 1, "message": "<текст причины>"}}
```

Поле `message` целиком под контролем устройства. Пример из настоящего агента:
`errorMessage=Data intent screen sharing is null cause user don't allow projection`.

**2. Сервер пересылает дословно** — содержимое не разбирается и не фильтруется
(измерено канарейкой: строка доходит до оператора байт в байт).

**3. Пульт принимает** (`WebRTCService.js:171-186`) — проверяются только наличие
`type` и `room`.

**4. Ветка разрыва** (`WebRTCService.js:236-240`):

```js
case 'disconnect':
  this.sessionEnded = true;
  if (signal.error && signal.error.message) {
    this.ui.showMessage(_t('error'), signal.error.message);
  }
```

**5. Сток** (`ui.js:404-408`):

```js
const messageTitleEl = document.createElement("div");
messageTitleEl.innerHTML = title;            // ← сток №1
const messageBodyEl = document.createElement("div");
messageBodyEl.classList.add("window-message-body");
messageBodyEl.innerHTML = text;              // ← сток №2
```

Тот же сток достижим из `onErrorReceived` (`WebRTCService.js:164-168`), куда
попадает сырое тело канала ошибок.

## Доказательство в настоящем браузере

Инструмент: `cli/pultpoc.py` — поднимает Chrome с отладочным протоколом,
переносит cookie сессии, открывает настоящую страницу пульта и вызывает её
собственный рендерер той же строкой, что присылает устройство.

```bash
python3 cli/pultpoc.py --base <host:8443> --mcc <СВОЁ устройство> --sink --headed --keep 120
```

Результат:

```

<img> из строки устройства:    <IMG>
атрибут onerror разобран как:  "document.title='RCPOC-FIRED'"
внешняя ссылка в DOM:          'https://evil.example/phish'
document.title:                'SafeMobile - Remote Control'   (не изменился)

нарушения CSP ПО СКРИПТУ: 1
  • Executing inline event handler violates the following Content Security Policy
    directive 'script-src 'self' 'nonce-…''
```

Скриншот: `artifacts/evidence/frc5-pult-render.png` — поддельный диалог «Сеанс
прерван сервером» с рабочей внешней ссылкой, отрисованный на странице
`/remotecontrol?mccId=…` под сессией администратора.

**Как это читать.** Экранирования нет вовсе: разметка разобрана в элементы DOM, а
инлайн-обработчик `onerror` браузер **попытался исполнить** — его срезала только
политика. Нарушение CSP в журнале и есть доказательство, что сток настоящий.

Для проверки без стенда: `python3 cli/frc5_local.py` поднимает локальную страницу
с той же CSP и настоящими `ui.js`/`lang.js`, скачанными со стенда.

## Что сдерживает и что не сдерживает CSP

Политика страницы пульта:

```
default-src 'self'; form-action 'self'; frame-ancestors 'none';
style-src 'self'; img-src 'self'; connect-src 'self';
script-src 'self' 'nonce-<uuid>';
```

| | |
|---|---|
| исполнение `<script>` и инлайн-обработчиков | **заблокировано** (нет `unsafe-inline`, nonce случайный на каждый ответ) |
| отрисовка произвольной разметки | **работает** |
| внешняя ссылка `<a href="https://…">` | **работает** — директивы `navigate-to` в политике нет |
| `<base href>` | **возможна** — директивы `base-uri` в политике нет |

Отсюда реалистичный потолок сегодня: **подмена интерфейса и фишинг в доверенном
окне консоли** — например, «Сеанс прерван, войдите повторно» со ссылкой на
страницу злоумышленника. Это не XSS. Но при любом ослаблении CSP (добавление
`unsafe-inline`, смена схемы с nonce, добавление доверенного CDN) последствия
становятся максимальными: на той же странице в `<meta name="_csrf">` лежит
CSRF-токен.

## Сквозное подтверждение (21.10.2026, комната 921)

После устранения [F-RC-11](F-RC-11-signal-without-type-kills-remote-control.md)
и перезапуска `arm` цепочка воспроизведена **целиком, одним прогоном**:

```
python3 cli/pultpoc.py --base sb-test.safe-mobile.ru:8443 --mcc 730 \
    --user <учётка> --password '<пароль>' --headed --wait 90
```

```
#  устройство получило WebRTCStart room=921 cid=22258
#  устройство подтвердило командой Answer
#  устройство отправило Disconnect с разметкой в error.message
   канарейка на странице:        True
   разметка стала ЭЛЕМЕНТОМ DOM: True (<DIV>)
   <img> из строки устройства:   True
   document.title:               'SafeMobile - Remote Control'  (не изменился)
```

Фактический `innerHTML`, построенный страницей из строки устройства:

```html
<div class="window-message-body">RCCANARY7781<div id="rcpoc" style="...">
<b>Сеанс прерван сервером.</b><br>Это НЕ сообщение консоли — эту разметку
сформировало УСТРОЙСТВО.<br><a id="rclink" href="https://evil.example/phish"
style="color:#06c">Войти повторно для продления сеанса</a></div>
<img src="x" id="rcimg" onerror="document.title='RCPOC-FIRED'"></div>
```

Никаких вызовов в странице не делалось: строку сформировало устройство, сервер
передал её дословно, браузер вывел в `innerHTML`. Скриншот результата —
`artifacts/evidence/frc5-pult-render.png`.

Ранее находка стояла на двух раздельных замерах (доставка — 20.10, сток —
21.10), потому что сквозной прогон блокировала F-RC-11. Эта оговорка снята.

## Рекомендации

1. **Экранировать**: использовать `textContent` вместо `innerHTML` для `title` и
   `text` в `showMessage` (`ui.js:404`, `ui.js:408`). Параметр `html`, где
   разметка нужна осознанно, оставить отдельным и применять только к данным,
   сформированным самой консолью.
2. **Не показывать текст устройства как есть.** Сообщения об ошибках с устройства
   отображать по коду (`errorCode`) из собственного словаря консоли, а исходный
   текст — только в журнале.
3. **Усилить CSP**: добавить `base-uri 'none'` и рассмотреть ограничение переходов.
4. Проверить остальные места, где данные устройства попадают в DOM консоли.
